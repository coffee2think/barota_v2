# 진입 열차 MVP 수정 계획

작성일: 2026-09-18  
상태: 계획 수립 완료 / 구현 전  
작업 목록: [작업 태스크](2026-09-18-arrival-mvp-fix-tasks.md)

## 1. 목표 및 범위

실제 스마트폰 테스트에서 발견된 다음 세 문제를 해결한다.

1. 선택한 출발역 → 목적지역의 진행 방향에 맞는 열차만 표시한다.
2. 표시할 열차를 출발역에 진입할 것으로 예상되는 순서대로 정렬한다.
3. 목적지 정차·미정차·확인 불가 상태를 데이터와 일치하는 색상 및 문구로 표시한다.

이번 작업은 계획 문서 작성이며 앱 코드는 변경하지 않는다. 구현 시에는 기존 Android/Kotlin/Compose 구조와 실시간 도착정보·시간표 연동을 활용한다.

### 제외 및 보류

- 독산역 추가와 최신 전체 역 데이터 교체: 사용자가 데이터를 제공한 후 별도 작업한다. 이번에 `stations.json`의 역 목록을 임의로 갱신하지 않는다.
- 선로 장애·지연 공지와 노란색 공지 카드: 사용자가 공지 API를 제공한 후 별도 작업한다. 임의의 지연 사례를 실제 공지처럼 표시하지 않는다.
- 환승 경로 탐색, 전체 노선망 구축, 신규 외부 API 도입, 서버 프록시, 자동 새로고침은 이번 범위에서 제외한다.
- 보류한 두 항목은 이번 MVP 완료 조건에 포함하지 않는다.

## 2. 현재 구현 확인 및 원인 후보

| 항목 | 코드에서 확인한 사실 | 구현 전 추가 확인 |
| --- | --- | --- |
| 방향 | `SeoulArrivalRepository`는 출발역 이름만 필터링한다. 목적지역은 정차 판정에만 사용한다. | 실제 응답의 상·하행/내·외선 값과 선택 경로의 대응 |
| 정렬 | `line → direction → arrivalSeconds` 순서로 정렬한다. | 0초·누락·음수 시간 및 진입/출발 상태의 실제 의미 |
| 정차 판정 | 종착역 일치 시 정차, 시간표 매칭·시각 비교로 정차/미정차를 판정한다. 키 누락·미지원·실패는 `UNKNOWN`이 된다. | 기기 빌드의 키 설정 여부, 열차번호/노선/방향/역명 매칭, 빈 시간표의 의미 |
| 색상 | 카드와 화면에 초록/빨강/기본색 분기가 이미 존재한다. 화면은 전체 목록의 최소 도착시간 열차를 따로 선택한다. | 실제 판정 전달, 첫 카드와 배경 일치, 테마·점멸·디버그 덮어쓰기 영향 |
| 방향 기준 | `Station`과 `stations.json`에는 역 ID·이름·호선만 있다. 역 목록은 이름순으로 정렬한다. | 현재 선택 가능한 역 사이의 검증된 진행 방향 기준 확보 |

따라서 1·2번은 현재 코드로 설명되는 구조적 문제다. 3번은 색상 구현 자체의 부재로 단정하지 않고, 실제 응답 → 판정 → 화면 상태 → 색상 경로를 추적한다. 기존 단위 테스트는 실제 시간표 제공 범위를 보장하지 않으며, UI 테스트는 주로 디버그 조작과 배경 태그를 검증한다.

## 3. 진행 방향 판정과 필터링

### 검토한 선택지

- 현재 역 목록의 배열 순서·역 ID·이름으로 상하행 추정: 철도 진행 순서를 뜻하지 않으므로 사용하지 않는다.
- 시간표에 목적지 열차가 있는지로 방향을 추정: 미정차 열차가 사라지고 매칭 실패가 방향 실패로 번지므로 사용하지 않는다.
- 기존 선택 가능 역을 대상으로 검증된 최소 방향 메타데이터와 별도 판정기를 사용: 최신 전체 역 데이터 교체 없이 방향 필터를 구현할 수 있어 채택한다.

### 결정 및 동작

- `RouteDirectionResolver`(가칭)를 별도 구성해 출발역·목적지역과 노선에서 진행 방향을 판정한다.
- 최초 구현 전 지원할 경로쌍과 근거를 정리한다. 실제 문제 재현 경로를 우선 포함하고, 현재 선택 가능한 경로의 지원/미지원 범위를 명시한다. 테스트용 임의 순서로 실제 서비스 방향을 확정하지 않는다.
- 방향 기준은 기존 역 선택 데이터와 분리한 최소 메타데이터로 관리한다. 최신 역 정보 전체 갱신은 하지 않는다. 검증 근거가 부족한 경로는 지원한다고 선언하지 않는다.
- 공통 노선이 하나이고 방향이 확정된 직통 경로는 해당 노선과 방향이 일치하는 열차만 남긴다. 같은 방향의 미정차 열차도 유지해 빨간 경고를 제공한다.
- 공통 노선이 여러 개인 경우 임의로 하나를 고르지 않는다. 기존 선택 화면에 필요한 최소 노선 선택을 제공하고, 선택 노선을 조회 상태와 필터에 전달한다.
- 2호선 순환 구간의 내·외선, 지선·분기 때문에 방향이 하나로 정해지지 않는 경우는 검증된 방향 선택을 제공한다. 근거가 없는 경로는 미지원 안내로 처리한다. 무조건 최단 방향을 가정하지 않는다.
- 공통 노선이 없는 환승 경로, 메타데이터 부족, 해석 불가 방향에는 `경로 방향을 확인할 수 없습니다` 또는 구체적인 선택 안내를 표시한다. 모든 열차를 대신 표시하지 않는다.
- API 방향 문자열은 내부 타입으로 정규화하되, 상행과 내선 등을 모든 노선에서 같은 값으로 간주하지 않는다. 빈 값이나 모르는 값은 임의 매칭하지 않는다.
- 필터링은 열차별 정차 시간표 요청보다 먼저 수행해 불필요한 호출을 줄인다.

방향 판정 불가와 정상 필터 후 열차 없음은 서로 다른 화면 상태로 구분한다. 미지원 안내는 안전한 예외 처리이며, 실제 재현 경로를 지원하는 것의 대체 완료 조건이 아니다.

## 4. 예상 진입 순서 정렬

- 방향 필터가 끝난 목록에 하나의 공통 정렬 정책을 적용한다.
- 정상적인 도착 예정 초가 있는 열차는 짧은 시간부터 정렬한다. 노선명·방향명은 시간보다 앞선 정렬 기준으로 사용하지 않는다.
- 누락·파싱 실패·음수는 확인 불가로 정규화해 뒤로 보낸다.
- 0초를 무조건 가장 가까운 열차로 보지 않는다. 현재 DTO의 `arvlCd`와 실제 응답을 확인해 유효한 진입/도착 0초, 출발 완료, 시간 미제공을 구별한다. 코드값 의미를 확인하기 전 임의 매핑하지 않는다.
- 출발역을 이미 떠난 것으로 확인된 열차는 진입 목록에서 제외한다. 상태로만 진입이 확인되지만 시간이 없는 열차의 우선순위는 실제 샘플을 근거로 정하고 테스트로 고정한다. 그 외 시간 미확인 항목은 뒤에 둔다.
- 같은 예상 시각은 검증된 API 순번이 있으면 이를 보조 기준으로 사용하고, 없으면 열차번호·안정적인 ID 순으로 정렬해 입력 순서 변화에 따른 흔들림을 줄인다.
- 화면 배경 판단은 별도 `minByOrNull` 계산 대신 최종 표시 목록의 첫 열차를 사용한다. 첫 열차가 `UNKNOWN`이면 뒤의 정차 열차를 대신 선택하지 않는다.
- 시간 없는 열차 간 실제 진입 순서는 보장할 수 없으므로 `도착시간 확인 중` 안내를 유지한다. 이 순서는 실시간 데이터 기반 예상이며 실제 운행 순서를 보장하지 않는다.

## 5. 정차 판정과 색상 표시

### 데이터 판정 점검

1. 개인정보·API 키를 제외한 재현 응답 fixture를 수집한다. 키 값 대신 키 설정 여부만 확인한다.
2. 실시간 열차번호와 시간표 열차번호의 형식, 노선·방향·역명, 조회 날짜/영업일, 시간값을 대조한다. 앞자리 0 제거 등 무조건적인 정규화는 하지 않는다.
3. 시간표 결과의 `totalCount`와 조회 범위를 확인한다. 조회 누락·부분 결과·API 미제공을 미정차로 단정하지 않는다.
4. 현재 출발역 매칭 + 목적지역 행 없음 → 미정차 규칙은 유지 가능성을 재검토한다. 해당 열차/구간의 조회 완전성과 제공 범위가 확인된 경우에만 미정차로 확정한다. 그렇지 않으면 `UNKNOWN`이다.
5. 목적지역 시각이 출발역 이후인지, 같은 운행 회차인지 검증한다. 중복 열차번호·자정 경계·24시 초과 표현·방향 불일치·잘못된 시간은 명시적으로 테스트한다.
6. 종착역=목적지 빠른 판정도 이름 비교만으로 오인하지 않도록 선택 노선·방향 문맥을 확인한다.

`UNKNOWN`은 실패를 감추는 정차 상태가 아니다. 키 미설정, 시간표 미지원, 매칭 불가, 불완전 응답 등의 원인을 내부 결과에 보존하고 사용자에게 필요한 수준으로 설명한다. 개별 시간표 실패로 실시간 열차 목록 전체를 실패시키지 않는다.

### UI 규칙

| 상태 | 카드 | 화면 배경 | 문구 |
| --- | --- | --- | --- |
| `STOPS` | 초록 | 첫 열차가 이 상태이면 초록 | 목적지 정차 |
| `DOES_NOT_STOP` | 기존 빨강 점멸 | 첫 열차가 이 상태이면 빨강 점멸 | 목적지 미정차 |
| `UNKNOWN` | 기본색 | 첫 열차 미확인 또는 열차 없음이면 기본색 | 정차 여부 확인 불가 및 필요한 이유 |

- 기존 색상 정책을 유지하면서 라이트·다크·동적 색상 환경의 글자 대비와 실제 배경을 검증한다. 색상만으로 상태를 전달하지 않는다.
- 디버그 테스트 버튼은 샘플 카드에만 영향을 주도록 분리한다. 실제 열차와 실제 첫 열차 배경을 강제로 덮어쓰지 않는다.
- 경로 변경 시 이전 경로의 목록·색상·디버그 상태가 남지 않도록 초기화하고, 늦게 도착한 이전 요청은 현재 화면을 덮어쓰지 못하게 한다.
- 같은 경로의 새로고침 실패로 이전 결과를 유지한다면 갱신 실패/기존 정보임을 명확히 표시한다.

## 6. 작업 순서와 검증

재현 자료 확보 및 지원 범위 확정 → 방향 판정/필터 → 예상 진입 정렬 → 정차 판정 보강 → 화면 연결 → 자동 테스트 → 스마트폰 검증 순으로 진행한다. 단계별 완료 기준과 의존성은 작업 태스크 문서에 기록한다.

### 자동 검증 계획

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat compileDebugAndroidTestKotlin
.\gradlew.bat lintDebug assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

마지막 명령은 연결된 기기 또는 에뮬레이터가 필요하다. UI 테스트 컴파일 성공과 실제 실행 성공을 구분한다. 태그·문구 검증 외에 실제 색상 및 첫 카드 순서를 검증한다.

### 실기기 검증 계획

- 사용자가 문제를 경험한 경로와 역을 뒤집은 경로에서 상·하행 필터를 확인한다.
- 지원하는 내·외선, 다중 공통 노선 선택, 미지원/환승 경로 안내를 확인한다.
- 서로 다른 진입 시간, 동률, 0초, 시간 미확인 및 새로고침 후 순서를 확인한다.
- 정차·미정차·확인 불가가 섞인 실제 운행 목록에서 카드 색상과 첫 열차 배경을 확인한다.
- 키 미설정/시간표 실패/빈 열차, 라이트·다크·동적 색상, 경로 변경 중 응답 역전을 확인한다.
- 실제 미정차 열차를 확보하지 못한 경우 fixture 검증과 실기기 미검증을 나누어 기록한다.

## 7. MVP 완료 조건

- 실제 문제 재현 경로에서 진행 방향이 검증되고 반대 방향 열차가 표시되지 않는다.
- 현재 선택 가능한 경로의 방향 지원 범위가 명시되며, 미지원 또는 추가 선택 필요 상태가 무필터 열차 목록으로 대체되지 않는다.
- 최종 목록은 공통 예상 진입 정책대로 정렬되고, 첫 열차와 화면 배경이 일치한다.
- 정차·미정차·확인 불가가 실제 판정과 일치하며, 매칭 실패를 정차/미정차로 오인하지 않는다.
- 자동 테스트·Lint·APK 빌드 및 실기기 핵심 흐름 검증 결과를 기록한다. 미실행 항목을 성공으로 처리하지 않는다.
- 최신 역 데이터와 공지 API 없이 이번 범위가 동작한다. 단, 방향 근거 또는 기존 시간표 접근이 확보되지 않아 재현 경로를 검증할 수 없으면 그 부분은 미완료로 남긴다.

현재 검증 결과: 관련 소스와 기존 테스트를 정적으로 확인했다. 앱 실행·API 호출·테스트 실행·스마트폰 재검증은 이 문서 작성에서 수행하지 않았다.
