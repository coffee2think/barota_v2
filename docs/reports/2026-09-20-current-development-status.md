# 현재 개발 현황 리포트

- 작성일: 2026-09-20
- 기준: 현재 작업 트리의 구현 코드와 자동 테스트
- 목적: 다음 MVP 개발 우선순위를 결정할 수 있도록 구현 범위, 동작 경계, 검증 상태를 한 문서로 정리한다.

## 한눈에 보는 현재 상태

앱은 **출발역·도착역 선택 → 경로의 노선·방향 결정 → 출발역 실시간 도착 열차 조회 → 열차별 목적지 정차 여부 판정 → 카드 표시** 흐름을 갖춘 Android Compose MVP다.

역 선택 카탈로그는 655개 역·24개 노선을 포함한다. 방향 판정용 그래프는 별도로 관리하며 현재 1~9호선, 16개 운행 서비스, 398개 고유 역을 포함한다. 두 데이터의 역할은 다르다. 카탈로그에 있는 모든 노선과 역이 곧바로 방향·정차 판정까지 지원되는 것은 아니다.

```text
역 선택 화면
  → 출발역/도착역 및 공통 노선 확인
  → 노선 그래프로 방향·subwayId 확정
  → 확정된 방향의 실시간 도착 열차만 조회·표시
  → 각 열차의 시간표를 출발역·목적지역에서 비교
  → 정차 / 미정차 / 확인 불가 상태로 카드 표시
```

## 만들어진 화면

| 화면 | 제공 기능 | 현재 상태 |
| --- | --- | --- |
| 역 선택 홈 | 출발역·도착역 선택, 출발/도착 맞바꾸기, 조회 진입 | 구현됨 |
| 역 검색 바텀시트 | 역명·호선 검색, 노선 배지, 출발역과 도착역 동일 선택 방지 | 구현됨 |
| 도착 정보 화면 | 선택 경로 요약, 방향 안내, 새로고침, 로딩·오류·빈 결과 표시 | 구현됨 |
| 공통 노선 선택 | 두 역에 공통 노선이 둘 이상일 때 조회 노선 선택 | 구현됨 |
| 도착 열차 카드 | 방향, 도착 예정, 현재 위치, 행선지, 급행/막차, 목적지 정차 상태 표시 | 구현됨 |
| 정차 상태 시각화 | 정차는 초록, 미정차는 빨간 점멸, 판정 불가는 기본 색상 | 구현됨 |
테스트용 가짜 열차 카드, 수동 상태 변경 버튼, 내부 진단 문자열은 모두 제거됐다. 화면에는 실제 조회 결과와 사용자에게 필요한 정차·미정차 정보만 표시한다.

## 화면 정보를 구성하기 위해 구현한 기능

### 1. 역 카탈로그와 선택 상태

- `stations.json`을 읽어 이름·노선 기준으로 정렬한다.
- 검색어가 역명 또는 노선명에 포함되면 결과로 보여 준다.
- 선택된 출발역·도착역의 이름과 소속 노선을 다음 화면으로 전달한다.
- 동일 역을 양쪽에 선택하지 못하게 막고, 출발·도착 맞바꾸기를 지원한다.

주요 코드: [`AssetStationRepository`](../../app/src/main/java/com/gilbit/barota/data/repository/AssetStationRepository.kt), [`StationSelectionViewModel`](../../app/src/main/java/com/gilbit/barota/ui/selection/StationSelectionViewModel.kt), [`StationSelectionScreen`](../../app/src/main/java/com/gilbit/barota/ui/selection/StationSelectionScreen.kt)

### 2. 노선·방향 결정

- `route_network.json`은 노선명, 서울시 API `subwayId`, 서비스별 방향 라벨, directed edge를 보관한다.
- Resolver는 역 순번을 비교하지 않고, 서비스의 정방향/역방향 그래프를 BFS로 탐색한다.
- 노선·방향이 하나로 결정되면 `Resolved`를 반환한다.
- 공통 노선이 둘 이상이면 노선 선택을 요구한다.
- 연결 경로가 없거나 환승이 필요한 경우 `Unsupported`를 반환한다.
- 순환선은 정·역방향 최단 edge 수를 비교하고, 거리가 같은 경우에만 `Unknown`을 반환한다.

현재 그래프 범위:

| 범위 | 데이터 상태 | 방향 판정 상태 |
| --- | --- | --- |
| 1호선 | 인천·신창·광명·서동탄 4개 서비스 | 직통 서비스 내부 지원 |
| 2호선 | 순환 본선·성수지선·신정지선 | 최단 방향 및 지선 지원 |
| 3·4·7·8·9호선 | 본선 | 양방향 지원 |
| 5호선 | 하남·마천 2개 서비스 | 각 서비스 내부 지원 |
| 6호선 | 본선·단방향 응암순환 | 각 서비스 내부 지원 |
| 1~9호선 외 | 역 카탈로그에는 일부 존재 | 그래프 미구축 |

8호선 암사 이후 연장 구간은 제공받은 노선도 기준으로 현재 그래프에서 제외되어 있다. 서로 다른 서비스 또는 환승이 필요한 경로는 단일 열차 경로로 추측하지 않는다.

주요 코드: [`RouteNetwork`](../../app/src/main/java/com/gilbit/barota/data/model/RouteNetwork.kt), [`RouteDirectionResolver`](../../app/src/main/java/com/gilbit/barota/domain/RouteDirectionResolver.kt), [`route_network.json`](../../app/src/main/assets/route_network.json)

### 3. 출발역 실시간 도착 열차 조회와 필터링

- 방향이 `Resolved`일 때만 서울시 실시간 도착 API를 호출한다.
- API 역명·노선 ID·방향값으로 출발역에 들어오는 열차를 필터링한다.
- 반대 방향, 다른 노선, 출발역이 다른 응답은 시간표 조회 전에 제외한다.
- 도착 예정 시간이 있는 열차를 앞에 정렬하고, 시간 미확인 열차는 뒤에 보낸다.
- 새로고침·중복 요청 방지·이전 요청 취소 및 늦게 도착한 응답의 화면 덮어쓰기 방지를 처리한다.

방향이 확정되지 않으면 열차 목록을 일부라도 보여 주지 않는다. 이 정책은 반대 방향 열차를 승차 후보로 오인시키지 않기 위한 안전 장치다.

주요 코드: [`ArrivalViewModel`](../../app/src/main/java/com/gilbit/barota/ui/arrival/ArrivalViewModel.kt), [`SeoulArrivalRepository`](../../app/src/main/java/com/gilbit/barota/data/repository/SeoulArrivalRepository.kt), [`ArrivalOrdering`](../../app/src/main/java/com/gilbit/barota/domain/ArrivalOrdering.kt)

### 4. 열차별 목적지 정차 판정

- 행선지가 목적지와 같으면 즉시 `STOPS`로 판정한다.
- 그 외에는 실시간 `btrainNo`의 선행 0을 제거하고 `K`, `S` 순서로 출발역 시간표 열차번호를 찾는다.
- 출발역에서 확정한 동일 시간표 열차번호로 목적지역을 조회한다.
- 목적지역의 시각이 출발역 이후면 `STOPS`로 판정한다.
- K/S 모두 출발역에서 찾지 못했거나, API 키·열차번호·시간 정보가 부족하면 `UNKNOWN`으로 반환한다.
- 출발역에서 열차를 찾았지만 목적지역 시간표에 없으면 현재는 `DOES_NOT_STOP`으로 반환한다.
- 열차별 시간표 조회는 동시 4건으로 제한하며, 한 열차의 판정 실패가 다른 열차 목록을 실패시키지 않게 처리한다.

주요 코드: [`SeoulTrainStopRepository`](../../app/src/main/java/com/gilbit/barota/data/repository/SeoulTrainStopRepository.kt), [`TrainArrival`](../../app/src/main/java/com/gilbit/barota/data/model/TrainArrival.kt)

## MVP 핵심 기능 진행표

체크 표기는 다음 의미를 가진다.

- `[x]` 구현 및 자동 테스트 보유
- `[~]` 구현됐으나 데이터·운영 범위 또는 실제 API 검증에 제약 있음
- `[ ]` 아직 구현하지 않음

| 출발역에 들어오는 열차 목록 조회 | [x] | 실시간 도착 API 호출, 로딩·오류·빈 상태, 새로고침 | 실제 API 장애·키 없는 환경 UX 점검 |

| 목적지 미정차를 안전하게 안내 | [~] | 시간표상 목적지 행이 없으면 미정차, 불확실하면 일부 경우 `UNKNOWN` | 공급자 응답 0건을 미정차로 확정해도 되는지 노선별 검증 |
| 실제 기기에서 전체 흐름 검증 | [ ] | Compose 테스트 소스 컴파일만 수행 | 에뮬레이터 또는 실기기에서 선택→조회→카드 확인 |

## 현재 MVP의 중요한 제한

1. **환승과 서로 다른 서비스 간 이동**

   출발역·목적지가 같은 노선 이름을 공유하더라도, 서비스 그래프가 연결되지 않으면 현재는 미지원이다. 환승 또는 서비스 변경이 필요할 수 있는 경로를 직통으로 표시하지 않는다.

2. **정차 판정의 실제 API 호환성**

   실제 API에서 독산역 `btrainNo=0472`를 `K472`로 변환해 시간표 1건을 확인했다. 다만 확인 시점의 강남역 2호선 표본은 K/S 모두 0건이어서 모든 노선에서 번호 체계가 동일하다고 단정할 수 없다. 이런 경우 앱은 미정차가 아닌 `UNKNOWN`으로 구분한다.

3. **미정차 확정의 보수성**

   목적지 시간표가 0건이라는 사실이 실제 미정차인지, 공급자 데이터 누락인지 아직 노선별로 검증되지 않았다. 검증 전에는 빨간 미정차 안내를 과신하면 안 된다.

4. **실시간 API 제공 범위**

   서울시 외 구간 또는 공급자 미제공 역은 그래프에 있어도 실시간 도착정보가 비어 있을 수 있다.

## 다음 개발 권장 순서

1. 대표 경로에서 실제 K/S 시간표 응답을 추가 수집해 노선별 계약 테스트로 고정한다.
2. 시간표용 역 코드 데이터를 확보해 역명 조회의 보조 조건으로 사용한다.
3. 목적지 시간표 0건을 미정차로 확정하는 정책을 실제 데이터 검증 결과에 따라 보강한다.
4. 실기기 또는 에뮬레이터에서 출발역 선택부터 도착 카드까지 검증한다.
5. 8호선 연장과 1~9호선 외 노선 그래프를 최신 공식 자료로 확장한다.
