# 첫 화면 경로 빠른 실행

## 1. 배경 / 문제

반복해서 사용하는 출발역·도착역 조합을 매번 선택해야 했다. 이미 저장하는 방향별 경로 사용 이력을 활용하면서, 사용자가 원하는 경로도 직접 저장하고 첫 화면에서 바로 조회할 수 있도록 한다.

## 2. 검토한 선택지

경로를 직접 저장하는 방식, 사용 이력만 자동 추천하는 방식, 둘을 함께 제공하는 방식을 검토했다. 사용자는 저장 경로와 자동 추천을 함께 제공하고, 경로를 누르면 추가 확인 없이 도착 정보를 열도록 선택했다. 첫 화면에서는 기존 역 선택 아래에 배치하며 별칭·순서 편집 없이 저장·해제를 제공하기로 했다.

## 3. 결정 및 이유

기존 SQLite 저장소와 화면 이동을 재사용한다. 저장 경로는 최근 저장순으로 유지하고, 추천은 사용 횟수·최근 사용순으로 최대 3개 제공한다. 저장 경로를 추천에서 제외해 중복 표시를 줄인다. 경로의 방향은 구분하며 저장 해제는 조회 이력을 삭제하지 않는다.

## 4. 구현 내용

* `feature/route-shortcuts` 브랜치를 main에서 생성했다. 기존 API 자료 변경은 수정·스테이징하지 않았다.
* DB 버전 2에 복합 키와 저장 시각을 가진 `saved_station_pair` 테이블을 추가했다. 버전 1→2 이전은 테이블 추가만 수행해 기존 역·경로 이력을 보존한다.
* 저장소에 전체 경로 이력·저장 경로 Flow와 저장·해제를 추가했다. 중복 저장은 기존 저장 시각을 유지하며 해제 후 재등록하면 새 시각을 기록한다.
* 순수 정렬 함수에서 역 ID를 현재 데이터에 연결하며 사라진 역과 동일 출발·도착 조합은 제외한다. 추천 동률은 출발·도착 이름과 ID로 결정한다.
* 기존 선택 영역 아래에 경로 저장, 저장한 경로, 자주 이용한 경로를 추가했다. 본문은 세로 스크롤하며 도착 정보 확인 버튼은 하단에 유지한다. 저장·해제 버튼과 바로 실행 클릭 영역을 분리했다.
* 빠른 실행과 일반 조회는 같은 처리로 경로 이력을 한 번 기록하고 기존 도착 정보 화면을 연다. 빠른 실행은 선택 값을 갱신하지만 역별 선택 횟수는 증가시키지 않는다. 실행·저장 중 중복 이벤트를 막는다.
* 저장·해제는 성공한 DB 상태를 관찰해 표시한다. 실패하면 화면의 저장 상태를 유지하고 메시지를 표시한다. 경로 목록 읽기 실패와 이력 기록 실패는 수동 조회 또는 화면 이동을 막지 않는다.

## 5. 검증 결과

* `testDebugUnitTest`: 전체 79개 통과, 실패 0. 추천 순위·제외·제한, 방향 구분, 저장·해제, 중복 실행, 쓰기·읽기 실패 처리 포함.
* `compileDebugAndroidTestKotlin`, `lintDebug`, `assembleDebug`: 성공.
* 연결된 Galaxy S23(Android 16)에서 SQLite 테스트 2개 통과. 버전 1→2 데이터 보존, 중복 저장, 해제·재등록, DB 재오픈과 방향별 저장을 검증했다.
* 전체 기기 테스트는 12개 중 9개 실패했다. 기존 도착 화면 테스트 4개와 역 선택 화면 테스트 5개에서 `No compose hierarchies found`가 발생했다. 기기 상태 확인 결과 화면이 절전·잠금 상태였다. 화면을 깨웠으나 잠금은 유지되어 사용자에게 해제를 요청했다. 화면 테스트 통과로 간주하지 않는다.
* 신규 Compose 테스트에는 1.5배 글꼴에서 스크롤로 경로에 접근하고 저장 버튼이 조회를 실행하지 않는 검증을 포함했다. 이 최종 소스는 컴파일했으며 기기 런타임 검증은 대기 중이다.

## 6. 남은 작업 / 보류 사항

* 잠금 해제된 기기에서 Compose 테스트를 재실행하고 작은 화면·큰 글꼴 및 실제 빠른 실행 후 도착 정보 화면을 확인한다.
* 별칭, 수동 순서 변경, 추천 숨기기, 별도 관리 화면, 위젯은 이번 범위에서 제외했다.
* 버전 설정·릴리스·병합·커밋은 수행하지 않았다.
