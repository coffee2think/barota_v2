# 시간표 열차번호 K/S 변환 및 재시도

## 1. 배경 / 문제

실시간 도착정보 API의 `btrainNo`는 숫자 문자열이지만 열차시간표 API의 `trainno`는 `K` 또는 `S` 접두어를 사용하는 별도 체계다. 기존 구현은 두 값을 그대로 비교하여 실제 시간표가 있어도 출발역에서 열차를 찾지 못했다.

## 2. 검토한 선택지

* 출발역과 목적지역에서 각각 K/S를 독립적으로 재시도하면 서로 다른 시간표 열차번호를 조합할 수 있다.
* 출발역에서 시간표 열차번호를 먼저 확정하면 같은 열차번호로 목적지역 정차 여부를 일관되게 확인할 수 있다.

## 3. 결정 및 이유

`btrainNo`의 선행 0을 제거한 뒤 `K`, `S` 후보를 만든다. 출발역에서 K를 우선 조회하고 정상 응답에 시간표 행이 없을 때만 S를 조회한다. 출발역에서 확정된 하나의 번호를 목적지역 조회에도 사용한다. K/S 모두 조회되지 않으면 미정차로 단정하지 않고 별도의 확인 불가 사유로 처리한다.

## 4. 구현 내용

* 숫자 실시간 열차번호 정규화와 K/S 후보 생성을 추가했다.
* 시간표 조회 순서를 출발역 K → 출발역 S → 목적지역 확정 번호로 변경했다.
* API 범위를 1~1000으로 확대하고 URL 경로를 한 번에 조립하여 실제 빈 인자(`//`)를 보존했다.
* 진단 모델에 시도한 시간표 열차번호와 확정 번호를 추가했다.
* 디버그 카드에 K/S 시도 및 확정 결과를 표시한다.
* 숫자가 아닌 실시간 번호와 K/S 모두 실패한 경우를 별도 진단 사유로 구분한다.

## 5. 검증 결과

* `gradlew testDebugUnitTest --no-daemon`: 성공, 59개 단위 테스트 통과
* `gradlew compileDebugAndroidTestKotlin lintDebug assembleDebug --no-daemon`: 성공
* 실제 API에서 독산역 상행 `btrainNo=0472`를 `K472`로 변환하고 실제 빈 URL 인자를 사용했을 때 시간표 1건을 확인했다.
* 같은 요청에서 빈 인자를 `%20` 공백으로 전달하면 0건이 반환되어, 연속 슬래시를 보존하는 URL 구성이 필요함을 확인했다.
* 확인 시점의 강남역 2호선 표본 4건은 K/S 모두 0건이었다. 해당 열차들은 앱에서 `TIMETABLE_TRAIN_NUMBER_NOT_FOUND`로 구분된다.

## 6. 남은 작업 / 보류 사항

시간표용 역 코드 데이터가 없어 이번 단계에서는 `stnCd`를 비우고 `stnNm`을 사용한다. 역 코드 자산을 확보하면 노선 데이터에 선택적으로 추가할 수 있다.
