# 2026-09-20 — 데이터 기반 노선 그래프 전환

## 1. 배경 / 문제

`RouteDirectionResolver`가 1호선 종로3가–독산 14개 역을 코드 배열로 보관하고 두 역의 배열 인덱스를 비교했다. 서울시 API의 `subwayId`도 `1001`로 고정되어 있어 노선 추가 때마다 Resolver에 노선별 분기를 추가해야 했고, 순환·분기 운행을 표현할 수 없었다.

`stations.json`은 역 선택·검색용 카탈로그이므로 철도 운행 순서로 해석하지 않고 기존 역할을 유지해야 했다.

## 2. 검토한 선택지

* 역마다 노선별 순번을 추가하는 방법은 직선 구간에는 단순하지만 순환과 분기에서 하나의 순번으로 운행 관계를 표현할 수 없어 제외했다.
* 운행 서비스별 directed edge를 별도 자산에 저장하고 그래프 도달성을 탐색하는 방법은 데이터가 조금 더 명시적이지만 직선·분기·순환을 같은 모델로 표현할 수 있다.

## 3. 결정 및 이유

별도 자산 `route_network.json`에 노선, 서울시 API 노선 ID, 운행 서비스, 정·역방향 API 라벨, 방향 있는 역 연결 관계를 저장한다. Resolver는 노선명에 따른 `if/else` 없이 선택된 노선의 모든 서비스 그래프를 탐색한다.

정방향 edge를 따라 목적지에 도달하면 `forward`, edge를 뒤집은 그래프에서 도달하면 `reverse` 방향이다. 둘 다 가능하면 순환선처럼 복수 방향이 유효한 상태이므로 임의 선택하지 않고 방향 선택 필요 상태(`Unknown`)로 반환한다.

## 4. 구현 내용

* `app/src/main/assets/route_network.json`
  * 1호선 `subwayId=1001`, `main` 서비스, 하행/상행 방향 라벨을 정의했다.
  * 기존 14개 역을 13개 directed edge로 이전했다.
  * 기존에 지원한 `역` 접미 별칭과 `서울`/`서울역` 및 API 역명 대응도 데이터로 이전했다.
* `RouteNetwork`, `RouteLine`, `RouteService`, `ServiceDirections` 직렬화 모델을 추가했다.
* `AssetRouteNetworkRepository`가 별도 자산을 읽고 Hilt가 `RouteNetworkRepository`로 주입하도록 연결했다.
* `RouteDirectionResolver`는 서비스별 정방향/역방향 인접 그래프를 만들고 BFS로 연결성을 판정한다. 노선 ID와 API 출발역 이름도 노선 데이터에서 `DirectionalRoute`로 전달한다.
* 기존 `LINE_ONE_DOWN_STATIONS`, `line == "1호선"` 분기, `subwayId = "1001"` 상수를 Resolver에서 제거했다.
* `stations.json`의 카탈로그 구조와 로딩 책임은 변경하지 않았다.

## 5. 검증 결과

* `testDebugUnitTest`: 49개 성공, 실패 0, 오류 0, 건너뜀 0.
* 실제 JSON의 14개 역 전체 출발지·목적지 조합에서 기존 상행/하행 결과를 검증했다.
* 별칭/API 역명, 명시적 노선 선택, 미지원·단절 경로, 분기 그래프, 순환 그래프의 복수 방향, 잘못된 edge의 fail-fast 검증을 추가했다.
* `compileDebugAndroidTestKotlin`: 성공.
* `lintDebug`: 성공, 오류 0, 경고 3.
* 실기기/에뮬레이터 UI 테스트 실행과 실제 서울시 API 호출은 이번 작업에서 수행하지 않았다.

## 6. 남은 작업 / 보류 사항

* 2호선은 순환 edge와 `내선`/`외선` 라벨을 데이터에 추가할 수 있다. 두 방향이 모두 유효한 구간은 현재 모호성으로 검출되므로, 실제 지원 단계에서 사용자가 방향을 선택하는 결과 타입과 UI를 추가해야 한다.
* 분기 노선은 실제 열차 운행 계통마다 서비스를 나누고 그 열차가 연속해서 운행하는 edge만 넣는다. 동일 출발·도착에 여러 서비스/방향이 성립하면 서비스 또는 방향 선택 정책이 추가로 필요하다.
* 노선 데이터 확대 전 운영기관 자료와 실제 API 방향 라벨을 대조해야 한다.
