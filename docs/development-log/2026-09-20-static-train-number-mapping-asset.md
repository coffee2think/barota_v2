# 런타임 SQLite 매핑을 정적 열차번호 자산으로 전환

## 1. 배경 / 문제

이전 작업에서는 운영 앱이 실시간 `btrainNo`와 시간표 `trainno`의 대응을 탐색한 뒤 SQLite에 저장하도록 구현했다. 이 방식은 설치 기기마다 발견 시점과 API 응답이 달라 서로 다른 매핑을 보유할 수 있고, 잘못 발견한 매핑이 기기별로 지속될 수 있었다. 최초 탐색 시 운영 앱이 출발역 전체 시간표를 조회해야 한다는 비용도 있었다.

동일 앱 버전에서는 모든 사용자가 같은 매핑 결과를 사용하도록, 개발 환경에서 매핑을 생성·검증한 뒤 앱 자산으로 배포하는 구조가 필요했다.

## 2. 검토한 선택지

* SQLite 자동 학습을 유지하면 시간표 변경에 즉시 대응할 수 있지만 결과가 설치별로 달라지고 운영 상태를 재현하기 어렵다.
* 노선별 변환 규칙을 운영 코드에 넣으면 자산은 작아지지만 새로운 번호 체계와 예외가 다시 코드 분기로 누적된다.
* 개발 PC에서 API 데이터를 수집해 개별 매핑 행을 JSON으로 생성하고 앱에서는 읽기만 하면 결과가 결정적이고 검증·배포 이력을 남길 수 있다.

## 3. 결정 및 이유

SQLite 저장소와 런타임 탐색·추가·삭제를 제거하고 `train_number_mappings.json`을 앱 자산으로 포함했다. 운영 앱은 복합 키로 정적 자산을 조회하며 매핑이 없으면 임의 추정 없이 `확인 불가`로 처리한다.

기본 키는 노선명, 정규화한 실시간 열차번호, 방향, 종착역, 열차 종류, 평일/주말 구분이다. 실시간 API와 시간표 API의 종착역 표기가 다른 경우가 있으므로 종착역을 제외한 나머지 키에서 `trainno`가 하나로 확정될 때만 보조 인덱스를 사용한다. 보조 키에 서로 다른 `trainno`가 존재하면 자동 선택하지 않는다.

## 4. 구현 내용

* `SqliteTrainNumberMappingStore`와 쓰기용 `upsert/delete` 계약을 제거했다.
* `AssetTrainNumberMappingStore`가 JSON을 한 번 읽어 정확한 복합 키 인덱스와 안전한 종착역 무관 보조 인덱스를 구성한다.
* `SeoulTrainStopRepository`에서 런타임 전체 시간표 탐색, 후보 점수 계산, 매핑 저장과 무효화 동작을 제거했다.
* 정적 매핑이 존재할 때만 해당 `trainno`로 출발역과 목적지역 시간표를 조회한다.
* `scripts/update-train-number-mappings.ps1`을 추가했다. 평일·주말 시간표를 1~9호선 공통 통과역과 2호선 지선, 6호선 응암순환 지점에서 수집하고, 페이지 처리·정규화·중복 및 충돌 검사를 수행한다.
* 2호선 실시간 표본에서 확인한 `8415→2415`, `8434→2434`, `7419→2419`, `6420→2420` 형식을 반영해 생성 단계에서 `2xxx` 시간표 번호의 `6xxx/7xxx/8xxx` 별칭 행을 정적으로 확장한다. 운영 앱에는 변환 로직이 없다.
* 기준 날짜 `2026-09-21` 평일과 `2026-09-20` 주말 데이터로 10,641개 매핑을 생성했다. 생성 과정의 정확한 복합 키 충돌은 0개였다.
* `-Verify` 옵션으로 API 호출 없이 버전, 필수 값, 복합 키 중복을 검증할 수 있다.

## 5. 검증 결과

* 전체 단위 테스트: 8개 스위트, 63개 테스트, 실패 0개, 오류 0개, 건너뜀 0개
* 정적 자산에 1~9호선, 평일/주말, 숫자형, K/S/C/E 접두어와 K 접미어 형식이 포함됨을 검증했다.
* 자산의 10,641개 행이 모두 자신의 복합 키로 조회되는지 검증했다.
* 종착역 무관 보조 인덱스가 하나의 `trainno`로 확정되는 경우에만 동작하도록 검증했다.
* 현재 실시간 표본과 교차 확인했으며, 2호선 별칭 추가 후 관찰한 `8415`, `7419`, `8434`, `6420`은 각각 정적 자산의 `2415`, `2419`, `2434`, `2420`으로 조회된다.
* SQLite, 런타임 매핑 쓰기, 런타임 전체 시간표 탐색 참조가 앱 코드에서 제거되었음을 확인했다.

## 6. 남은 작업 / 보류 사항

* 실시간 API는 현재 운행 중인 열차만 제공하므로 여러 시간대의 표본을 추가 수집해 별칭 체계와 단축 운행을 계속 검증해야 한다.
* 교차검증 당시 8호선 주말 실시간 `8241`은 같은 기준일 시간표 자산에 대응 행이 없었다. 잘못 추정하지 않고 `확인 불가`로 남기며, 다른 시간대 또는 임시 시간표 여부를 추가 확인한다.
* 시간표 개편 시 스크립트를 다시 실행하고 자산 변경 내역과 충돌 보고서를 검토한 뒤 앱을 배포해야 한다.
