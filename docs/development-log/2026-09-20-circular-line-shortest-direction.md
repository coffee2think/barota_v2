# 순환선 최단 방향 판정

## 1. 배경 / 문제

2호선 강남역에서 서울대입구역으로 이동할 때 두 역의 공통 노선은 2호선 하나지만, Resolver가 내선과 외선 모두 목적지에 도달할 수 있다는 이유로 방향을 결정하지 못했다. 순환선에서는 양방향 모두 연결되는 것이 정상이며, 단순 도달 가능 여부만으로는 실제 탑승 방향을 정할 수 없다.

## 2. 검토한 선택지

* 2호선 역 순서를 별도로 하드코딩해 방향을 지정하는 방법은 현재 데이터 기반 그래프 구조를 훼손하므로 사용하지 않았다.
* 두 방향을 사용자에게 항상 선택하게 하는 방법은 명확히 더 짧은 경로가 있는 경우에도 불필요한 선택을 요구한다.
* 기존 방향 edge 그래프에서 각 방향의 최단 edge 수를 계산하고 비교하는 방법은 노선별 분기 없이 순환선과 향후 다른 그래프에도 적용할 수 있다.

## 3. 결정 및 이유

각 서비스의 정방향과 역방향 그래프에서 BFS로 최단 거리를 계산하고, 전체 후보 중 최단 거리의 방향을 선택한다. 최단 거리가 같은 서로 다른 방향이 있을 때만 기존의 방향 선택 필요 상태를 유지한다.

## 4. 구현 내용

* `RouteDirectionResolver`의 boolean 경로 존재 검사를 최단 edge 거리 계산으로 변경했다.
* 여러 서비스와 방향 후보 가운데 최단 거리 후보를 선택하도록 변경했다.
* 강남 → 서울대입구는 내선, 서울대입구 → 강남은 외선으로 판정하도록 테스트를 추가했다.
* 동일 거리의 양방향 순환 그래프는 여전히 모호한 방향으로 처리하도록 테스트했다.

## 5. 검증 결과

* `gradlew testDebugUnitTest --no-daemon`: 성공, 54개 단위 테스트 통과
* `gradlew lintDebug assembleDebug --no-daemon`: 성공, lint 및 디버그 APK 빌드 통과
* 강남 → 서울대입구: 6개 edge인 내선으로 판정
* 서울대입구 → 강남: 6개 edge인 외선으로 판정
* 양방향 최단 거리가 같은 인공 순환 그래프: 방향 선택 필요 상태 유지

## 6. 남은 작업 / 보류 사항

실제 운행이 최단 거리와 다른 특수 서비스가 추가되는 경우 서비스 우선순위나 운행 패턴 정보를 노선 데이터에 명시해야 한다.
