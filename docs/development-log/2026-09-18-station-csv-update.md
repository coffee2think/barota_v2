# 2026-09-18 — 제공 CSV 기준 역 정보 갱신

## 1. 배경 / 문제

사용자가 `D:\Dev\workspace\barota_v2\dev-resources\docs\서울교통공사_노선별 지하철역 정보.csv`를 기준으로 역 정보를 갱신하도록 요청했다. 기존 앱 데이터는 61개 역만 포함해 독산 등 많은 역을 선택할 수 없었고 일부 환승 노선도 빠져 있었다. 다른 CSV나 XLSX, 외부 웹 자료는 데이터 소스로 사용하지 않았다.

## 2. 검토한 선택지

- 제공 CSV를 기존 Station 모델의 JSON으로 변환: 런타임과 Repository를 변경하지 않고 전체 목록을 반영할 수 있다.
- 같은 이름의 모든 행을 단순 병합: 환승역 통합은 가능하지만 서로 다른 신촌·양평 역을 잘못 합칠 수 있다.
- 동명 별개 역 이름에 노선을 덧붙이기: 화면 구분은 쉬우나 역 이름을 그대로 전달하는 기존 API 조회에 영향을 준다. 이름 대신 ID와 노선 목록으로 구분하기로 했다.

## 3. 결정 및 이유

제공 CSV의 CP949 인코딩과 실제 열 이름 `전철역코드`, `전철역명`, `호선`을 사용한다. CSV에는 24개 노선, 799개 행이 있으며 영문 접미사 C가 있는 역 코드도 존재하므로 코드 문자열을 보존한다. 환승역은 이름으로 묶되 신촌(2호선/경의중앙선)과 양평(5호선/경의중앙선)은 별도 ID로 유지한다. 기존 61개 역의 이름과 ID를 보존해 선택 시 동일 역 판정의 안정성을 유지한다.

노선 표시는 기존 앱 표기에 맞춰 `01호선` 등 앞자리 0을 제거하고 `경의선`을 `경의중앙선`, `인천선`을 `인천1호선`으로 정규화했다. 총신대입구·이수는 기존 `총신대입구(이수)`로, GTX-A의 서울은 서울역으로 통합했다. 역 순서·운행 경로·API 지원 범위는 이 CSV에서 추정하거나 확장하지 않았다.

## 4. 구현 내용

- `app/src/main/assets/stations.json`: 655개 역, 24개 노선으로 갱신. 독산 추가, 신설동 2호선·우이신설경전철 추가 등 CSV의 환승 정보를 반영했다.
- `scripts/update-stations.ps1`: PowerShell 7용 변환/검증 도구. 기본 실행은 JSON 변경 패치를 출력하며 실제 파일 변경은 apply_patch로 적용했다. `-Verify`는 CSV 기준 전체 결과와 현재 JSON의 일치를 검사한다. 기존 JSON의 ID를 재사용하므로 반복 실행에도 ID가 유지된다.
- `StationAssetTest.kt`: JSON 역 개수·필수 필드·ID 중복·노선 중복, 독산/환승역 및 동명 별개 역의 회귀 테스트를 추가했다.
- Station 모델, Repository, 도착 정보 기능은 변경하지 않았다. 원본 CSV 및 기존 개발 기록은 수정하지 않았다.

## 5. 검증 결과

- `./scripts/update-stations.ps1 -Verify` 통과: 799개 원본 행에 대한 결과가 655개 역 및 24개 노선의 JSON과 일치한다.
- HEAD의 기존 역 목록과 비교해 61개 역의 이름과 ID가 모두 유지됨을 확인했다.
- 독산, 서울역, 신설동, 총신대입구(이수), 신촌·양평의 분리 결과를 확인했다.
- `git diff --check` 통과.
- `testDebugUnitTest assembleDebug` 실행을 시도했으나 환경 오류로 실행하지 못했다. 최초 Android 사용자 설정 경로 `C:\.android` 오류는 작업 영역의 ANDROID_USER_HOME 지정으로 우회했으나, SDK에 프로젝트의 `android-37.0` 타깃이 없어 의존성 결정 단계에서 실패했다. 추가한 JUnit 테스트를 포함해 테스트 통과나 빌드 성공으로 간주하지 않는다.
- 실기기·에뮬레이터 및 실제 API 조회는 수행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 필요한 SDK 설치 후 단위 테스트와 APK 빌드를 다시 수행한다.
- 실기기에서 역 검색/선택 및 새 노선의 API 지원 여부를 확인한다. 데이터에 노선이 포함된 것이 기존 도착·시간표 API의 해당 노선 지원을 보장하지는 않는다.
- 신촌·양평은 선택 화면의 노선 표시와 ID로 구분하지만 이름만 사용하는 기존 API 경로의 동명역 구분은 별도 검토가 필요하다.
