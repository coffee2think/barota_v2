# 2026-09-18 — 상·하행 판정 구현 전 계획

## 배경 / 문제

사용자가 MVP 작업 태스크를 참고해 상·하행 판정을 구현하되 독산 → 종로3가로 테스트하고, 구현 전에 계획을 수립하도록 요청했다.

## 검토 및 결정

현재 Repository는 출발역만 필터링하며 목적지 진행 방향과 무관한 열차도 정차 조회한다. 역 선택 JSON의 배열이나 역 ID는 운행 순서를 의미하지 않으므로 사용하지 않는다. 지정 경로의 검증된 방향 메타데이터와 순수 판정기를 분리하고 원본 API 방향을 정차 요청 전에 필터링하기로 계획했다. 다중 노선/순환/미지원 구간은 임의 선택 대신 명시적 선택 또는 안내 상태를 사용한다. 이번 사용자 요청의 방향 기능(T01~T03)과 별도 정렬·정차·색상 작업(T04~T06)을 구분한다.

## 작성 내용

`docs/plans/2026-09-18-route-direction-implementation-plan.md`에 현재 코드, 데이터 확인 사실, 근거 확인 절차, 순수 판정기·조회·화면 연결 계약, 독산/종로3가 및 역전 테스트, 검증 명령과 완료 기준을 기록했다. 아직 방향 앱 코드는 변경하지 않았다.

## 검증 및 남은 작업

태스크/기존 MVP 계획, Repository/DTO/모델, 도착 ViewModel/화면, 선택 ViewModel/탐색 인자 및 기존 테스트를 확인했다. 제공 CSV에서 지정 구간의 역과 외부코드를 확인했다. 실제 도착정보 응답, 운영 방향 근거 대조, 구현, 자동 테스트 및 실기기 검증은 아직 수행하지 않았다. 다음 단계는 방향 근거 확인 후 계획의 순서로 구현하는 것이다.
