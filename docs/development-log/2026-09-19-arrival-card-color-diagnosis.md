# 2026-09-19 도착정보 카드 색상 미작동 진단

## 1. 배경 / 문제

실제 도착정보 카드가 정차 여부에 따라 초록 또는 빨강으로 표시되지 않고 기본색으로 보이는 현상을 진단했다. UI 색상 분기, 정차 판정, 시간표 API 요청·매칭, 디버그 덮어쓰기를 분리하고 실제 서울시 API 응답과 대조할 필요가 있었다.

## 2. 검토한 선택지

- 코드와 합성 단위 테스트만 확인: 비밀정보를 사용하지 않지만 실제 API의 빈 결과와 열차번호 호환성을 확정할 수 없다.
- 실제 API를 읽기 전용으로 대조: 로컬 키를 서울시 공식 API에 전송해야 하지만, 현재 데이터에서 어느 조건이 결과를 소거하는지 확인할 수 있다.

사용자 승인에 따라 실제 API를 대조하되 키, 키 포함 URL, 원본 응답 및 실제 열차번호는 출력하거나 저장하지 않았다.

## 3. 결정 및 이유

카드 색상 코드 자체보다 `destinationStopStatus`가 `UNKNOWN`이 되는 상류 원인을 근본 원인으로 판단했다. 실제 2호선 열차는 검색일시 없이 출발역·목적지역 모두 시간표가 매칭됐지만 앱과 동일하게 현재 `searchDt`를 추가하면 0건이 됐다. 독산 1호선은 검색일시를 제거해도 실시간 열차 세 건 모두 양쪽 시간표가 0건이었다.

따라서 `searchDt` 필터 동작, 독산/코레일 구간의 제공 범위 또는 열차번호 호환성, 실패 원인을 버리는 `UNKNOWN` 축약을 분리해 기록했다. 디버그 버튼이 실제 카드까지 덮어쓰는 문제는 별도 보조 원인으로 분류했다.

## 4. 구현 내용

- 앱 코드는 변경하지 않았다.
- `docs/reports/2026-09-19-arrival-card-color-diagnosis.md`에 코드 흐름, 실제 API 대조 결과, 확정·유력·추가 검증 필요 원인, 영향 범위와 우선순위별 권고안을 작성했다.
- 실제 응답 수치는 집계값만 기록하고 인증 정보와 원본 응답은 보존하지 않았다.
