# 2026-09-20 — 1~9호선 노선 그래프 데이터 확장

## 1. 배경 / 문제

앞선 데이터 기반 전환에서는 기존 지원 범위인 1호선 종로3가–독산 14개 역만 첫 데이터셋으로 옮겼다. 이후 사용자가 첨부한 1페이지 노선도를 기준으로 1~9호선의 본선, 순환선, 지선 및 분기 역 순서를 제공하고 이를 노선 마스터 데이터로 구축하도록 요청했다.

단순 `stationOrder`는 순환과 분기를 표현하지 못하므로 앞서 결정한 운행 서비스별 directed edge 구조를 유지해야 했다.

## 2. 검토한 선택지

* 제공된 역 순서를 노선마다 하나의 배열로 저장하는 방식은 1·5호선 분기와 2호선 순환·지선을 표현할 수 없어 사용하지 않았다.
* 공통구간을 각 목적지 계통의 서비스 그래프에 포함하는 방식은 edge가 일부 중복되지만, 실제로 한 방향으로 연결되는 범위와 환승이 필요한 분기 사이를 구분할 수 있다.
* 6호선 응암순환에 자동 역방향을 만드는 방식은 운행하지 않는 방향을 생성하므로 `reverse`를 선택 항목으로 변경했다.

## 3. 결정 및 이유

사용자 제공 순서를 directed edge로 변환하고 다음 16개 서비스로 구분했다.

* 1호선: `incheon`, `sinchang`, `gwangmyeong`, `seodongtan`
* 2호선: `circle`, `seongsu_branch`, `sinjeong_branch`
* 3·4·7·8·9호선: 각 `main`
* 5호선: `hanam`, `macheon`
* 6호선: 단방향 `eungam_loop`, 양방향 `main`

2호선 순환 본선은 어느 두 역 사이에서도 내선·외선 경로가 모두 존재하므로 Resolver가 한 방향을 임의로 선택하지 않고 방향 선택 필요 상태로 남긴다. 1·5호선의 서로 다른 분기 사이와 2호선 본선–지선 사이처럼 열차 변경이 필요한 경로도 하나의 직통 서비스로 합치지 않았다.

## 4. 구현 내용

* `route_network.json`을 버전 2로 갱신하고 1~9호선, 16개 서비스, 서비스 기준 634개 edge, 398개 고유 역을 수록했다.
* `ServiceDirections.reverse`를 선택 값으로 변경하여 단방향 순환을 표현했다.
* `scripts/update-route-network.ps1`을 추가했다. 제공된 원본 순서를 보존하면서 JSON을 생성하고 다음을 검증한다.
  * 모든 edge 역이 `stations.json`에 존재하는지
  * 해당 역에 대상 노선이 등록되어 있는지
  * 서비스 ID가 노선 안에서 중복되지 않는지
  * 빈 서비스와 자기 자신을 잇는 edge가 없는지
  * 생성된 JSON이 스크립트 결과와 일치하는지 (`-Verify`)
* 제공 자료의 `당고개`는 현재 카탈로그 명칭 `불암산`으로 저장하고 별칭을 추가했다.
* 제공 자료의 `자양(뚝섬한강공원)`은 카탈로그 노드 `자양`으로 저장하되 별칭과 API 역명을 보존했다.
* 서울시 실시간 도착 API를 키가 노출되지 않는 읽기 전용 호출로 확인했다.
  * 2호선 성수·신정지선: 제공 순서 방향 `내선`, 역방향 `외선`
  * 6호선 응암순환: 제공 순서의 역촌 도착 열차 `하행`
  * 8호선 모란→암사 제공 순서: `상행`, 역방향 `하행`

## 5. 검증 결과

* 노선 생성 스크립트 및 `-Verify`: 성공 — 9개 노선, 16개 서비스, 634개 서비스 edge, 398개 고유 역.
* `testDebugUnitTest`: 52개 성공, 실패 0, 오류 0, 건너뜀 0.
* 1~9호선 ID, 전체 데이터 규모, 각 직선 노선의 양방향 끝점, 1·5호선 분기, 2호선 두 지선, 2호선 순환 방향 모호성, 6호선 단방향 순환을 단위 테스트로 검증했다.
* `compileDebugAndroidTestKotlin`: 성공.
* `lintDebug`: 성공, 오류 0, 경고 3.
* 실기기/에뮬레이터 UI 테스트는 실행하지 않았다.

## 6. 남은 작업 / 보류 사항

* 사용자 제공 PDF가 미개통으로 표시한 8호선 암사역사공원–별내 구간은 이번 자산에서 제외했다. 다만 2026-09-20 실제 API 확인에서는 잠실 상행 열차의 행선지가 `별내`로 반환되어 제공 자료와 현재 운행 상태가 다르므로, 최신 노선 기준으로 전환할 때 별도 데이터 갱신이 필요하다.
* 2호선 순환 본선은 내선·외선이 모두 유효하다. 현재는 모호성을 안전하게 반환하며, 실제 조회 지원을 위해 방향 선택 UI 또는 명시적인 경로 선택 정책이 필요하다.
* 6호선 본선에서 응암순환으로 이어지는 운행은 응암 전후로 API 방향 라벨이 달라질 수 있어 하나의 `DirectionalRoute`로 합치지 않았다. 방향 전환을 포함하는 다중 구간 모델이 필요하다.
* 제공 노선도는 역 연결 순서의 근거이며 모든 시간대의 실제 직통 열차 운행을 보장하지 않는다. 개별 열차의 목적지 정차 여부는 기존 시간표 판정기가 계속 담당한다.
