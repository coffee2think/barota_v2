# 2026-09-19 도착 열차 카드 디버그 진단 표시

## 1. 배경 / 문제

도착정보 카드가 기본색인 `UNKNOWN`으로 표시될 때 카드에 들어온 실시간 열차 데이터와 시간표 판정 실패 이유를 화면에서 확인할 수 없었다. 기존 모델은 최종 상태만 보존했고, API 키 누락·미지원 노선·출발역 시간표 불일치·조회 실패가 모두 같은 `UNKNOWN`으로 축약되었다.

## 2. 검토한 선택지

- Repository 로그만 추가: 개발 로그캣에서는 확인할 수 있지만 사용자 스마트폰 화면만으로 재현할 때 필요한 정보를 확인하기 어렵다.
- `TrainArrival`에 자유 형식 문자열을 저장: 구현은 간단하지만 테스트와 후속 처리에서 원인 유형을 안정적으로 구분하기 어렵다.
- 구조화된 판정 사유와 매칭 건수를 저장하고 디버그 카드에서 출력: 모델 변경 범위는 늘지만 실제 판정과 표시 상태를 구분하고 회귀 테스트할 수 있다.

## 3. 결정 및 이유

`DestinationStopDecision`과 `DestinationStopDiagnostic`을 추가해 상태, 판정 사유, 출발역·목적지역 시간표 매칭 건수를 함께 전달한다. 판정 사유는 enum으로 관리하고 한국어 설명은 UI 계층에서 변환한다. 내부 열차번호와 진단 정보가 일반 사용자 화면에 노출되지 않도록 진단 영역은 `BuildConfig.DEBUG`에서만 표시한다.

디버그 색상 미리보기가 실제 상태를 덮어쓰는 기존 동작은 이번 작업에서 변경하지 않는다. 대신 카드에 실제 판정과 화면 표시 판정이 다를 때 덮어쓰기 사실을 명시해 혼동을 줄인다.

## 4. 구현 내용

- 열차 모델에 구조화된 정차 판정 진단 정보를 추가했다.
- 시간표 Repository가 종착역 일치, 키/열차번호 누락, 미지원 노선, 출발·목적지 매칭 실패, 이후 정차, 이미 지난 목적지, 시각 비교 실패를 구분해 반환한다.
- 개별 시간표 조회 예외는 `LOOKUP_FAILED`로 보존하면서 기존처럼 열차 목록은 유지한다.
- 디버그 카드에 노선, 방향, 열차번호, 종착역, 실제 판정, 판정 사유, 시간표 매칭 건수, 도착 초·상태·시간 종류·정렬 키를 출력한다.
- 단위 테스트에서 상태뿐 아니라 사유와 매칭 건수를 검증하고, Compose 테스트에 `UNKNOWN` 카드 진단 문구 검증을 추가했다.

## 5. 검증 결과

- `testDebugUnitTest`: 성공.
- `compileDebugAndroidTestKotlin`: 성공.
- `lintDebug`: 성공(오류 0, 기존 버전 관련 경고 3건).
- 최초 샌드박스 실행은 Android SDK와 Kotlin 데몬 경로 접근 제한으로 실패했으며, 동일 명령을 승인된 환경에서 다시 실행해 `BUILD SUCCESSFUL`을 확인했다.
- 연결 기기 또는 에뮬레이터에서 Compose UI 테스트 실행과 실제 카드 레이아웃 육안 검증은 수행하지 않았다.

## 6. 남은 작업 / 보류 사항

- 실제 독산 → 종로3가 조회에서 `ORIGIN_TRAIN_NOT_FOUND`와 0건 매칭이 카드에 표시되는지 실기기에서 확인한다.
- 진단 결과를 바탕으로 `searchDt` 처리와 코레일 구간 시간표 매칭을 별도 수정한다.
- 디버그 미리보기를 테스트 카드에만 한정하는 기존 보류 작업은 별도로 진행한다.
