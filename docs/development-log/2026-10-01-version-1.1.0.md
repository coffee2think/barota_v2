# 앱 버전 1.1.0 갱신

## 1. 배경 / 문제

`v1.0.0` 이후 역 선택 개인화 정렬 기능, 도착 정보 화면 색상 대비 개선, Gradle 빌드 설정 정리가 `main`에 반영되었다. 앱 설정은 여전히 `versionName=1.0`, `versionCode=1`이어서 현재 기능 상태를 구분할 새 앱 버전이 필요했다.

사용자가 실제 기기에서 현재 `main`의 주요 동작이 정상임을 확인했다.

## 2. 검토한 선택지

* `1.0.1`은 버그 수정 중심의 패치 버전에 적합하지만, 이번 범위에는 사용자별 역 정렬이라는 신규 기능이 포함되어 있다.
* `1.1.0`은 기존 호환성을 유지하면서 기능을 추가한 현재 변경 범위에 맞는다.

## 3. 결정 및 이유

Semantic Versioning의 마이너 버전 증가에 맞춰 `versionName`을 `1.1.0`으로 변경하고, Android 배포 식별자인 `versionCode`를 기존 1보다 큰 2로 변경한다.

Git 태그 `v1.1.0`은 이 버전 커밋이 `main`에 병합된 뒤 병합 커밋을 대상으로 생성한다. 작업 브랜치에는 릴리스 태그를 미리 만들지 않는다.

## 4. 구현 내용

* `app/build.gradle.kts`의 `versionName`을 `1.1.0`으로 갱신했다.
* `app/build.gradle.kts`의 `versionCode`를 `2`로 갱신했다.

## 5. 검증 결과

* 사용자가 버전 변경 전 현재 기능을 실제 기기에서 정상 작동하는 것으로 확인했다.
* `testDebugUnitTest`: 74개 성공, 실패 0, 오류 0, 건너뜀 0.
* `compileDebugAndroidTestKotlin`: 성공.
* `lintDebug`: 성공, 오류 0개. 기존 코드 정리 및 도구·의존성 업데이트 관련 경고 8개가 남아 있다.
* `assembleRelease`: 성공. 생성된 릴리스 메타데이터에서 `versionCode=2`, `versionName=1.1.0`을 확인했다.
* 샌드박스에서는 사용자 Android SDK의 `core-lambda-stubs.jar` 접근이 거부되어 중단됐고, 같은 검증을 실제 사용자 권한으로 다시 실행해 성공했다.

## 6. 남은 작업 / 보류 사항

* 버전 브랜치를 `main`에 병합한다.
* 병합된 `main`에서 `v1.1.0` 태그를 생성하고 원격 저장소에 푸시한다.
* 필요하면 GitHub Release와 배포용 산출물을 생성한다.
